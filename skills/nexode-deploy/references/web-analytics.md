# Automatic web analytics

For a new frontend or landing, include Nexode analytics unless the user opts out. On an existing site, perform this integration when requested and preserve deliberately paused collection during unrelated maintenance. Backend computes do not support web analytics.

1. Create/select the intended compute and call `nexode_compute_analytics` with its ID. It returns `enabled`, `domains`, the exact public `script`, totals and daily/breakdown data. Reading needs `compute:read`; configuration needs `compute:write`. These are ordinary owner API-key tools, with no dashboard login.
2. Inspect the actual source and install the returned script exactly once in the shared document/root. HTML and Vite use the root `index.html` head. Next.js App Router uses the shared root layout and a compatible Script strategy; verify the rendered `src` and `data-site`. Other stacks use their shared document template. Preserve current scripts, consent integrations and unrelated source changes. Do not invent the backend URL, resource ID or a different provider's snippet.
3. If already installed for this compute, reuse it. An existing different `data-site` needs inspection: do not blindly duplicate or replace another app's integration. For restrictive CSP, allow only the actual returned backend origin in `script-src` and `connect-src`, preserving existing policy. Do not disable CSP or broadly allow all origins. API keys never go into public code or frontend variables.
4. Call `nexode_compute_configure_analytics` with `enabled: true` for the authorized setup. It enables the collector only; it does not modify repository files. Build and test the real app, commit/push the integration using local Git, verify the remote SHA and redeploy the selected compute. For first creation, a second deployment may be necessary once the compute ID exists.
5. Verify the final public page loads the correct script and site ID, visit a page with a normal browser, and query `nexode_compute_analytics` again. Confirm views increase when possible. Keep Do Not Track, Global Privacy Control and existing consent choices intact; report an empty or blocked collector honestly. Do not create fake events or claim event verification from an enabled flag.

The tracker supports client-side history navigation. It stores a daily random identifier in first-party local storage, sends no cookies, and discards URL queries/fragments and referrer paths. IP addresses and form values are not saved by the analytics store. Visitors are approximate browser/day counts in UTC and may count a returning browser again on another day. Retention is 30 days; there is no history before installation.
